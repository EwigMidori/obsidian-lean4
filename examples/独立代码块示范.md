# Lean 4 独立代码块示范

这篇笔记不使用 `session`，因此每个可检查代码块都是独立的 Lean 文档。把光标移到块内后，
插件检查当前块，并在目标面板中显示光标位置的证明目标。
这些示例只使用默认基础 Lean，不需要自己建立项目。若首次使用时提示缺少 Lean，
点击 **Prepare Lean**，准备好后继续检查。

## 相同名称，互不冲突

第一个块定义 `answer`：

```lean title="第一个 answer"
def answer : Nat := 42

example : answer = 42 := by
  rfl
```

第二个块也定义 `answer`，不会与上一个块发生重复定义冲突：

```lean title="第二个 answer"
def answer : Nat := 7

example : answer = 7 := by
  rfl
```

## 错误只属于当前块

下面故意给出一个类型错误。错误应该只显示在这个块：

```lean title="故意保留的类型错误"
def wrong : Nat := "这不是自然数"
```

后面的正确证明仍然可以独立通过：

```lean
example (n : Nat) : n + 0 = n := by
  rfl
```

## 前置定义也必须写在本块中

这个块不能引用前面定义的 `answer`，因此它故意报错：

```lean
#check answer
```

需要使用 Mathlib 时，再切换到高级已有项目模式，并在每个需要它的块顶部写
`import Mathlib`；该项目应已配置、构建相应依赖。这里的基础示例不需要 Mathlib。

## 只展示，不检查

在 `lean` 后加 `check=off`，适合语法草稿、不完整的证明或
希望保留的错误示例。插件显示 **Display only**（仅展示），不会把它送给 Lean：

```lean check=off title="不完整证明，只展示语法"
example (P Q : Prop) : P → Q := by
  -- 这里故意不补全证明，只展示语法结构。
```

```lean4 check=off title="定义写到一半"
def unfinished : Nat :=
```

旧笔记中的 `lean-example` 和 `lean-off` 仍然表示仅展示；新笔记可以统一使用
`lean check=off`，让语言名称与检查策略各自清晰。

## 标题只影响展示

`title` 不会注入 Lean 代码，也不是模块或命名空间。只修改标题不增加代码版本，
不会让已经检查过的代码重新检查。含空格的标题使用双引号或单引号：

```lean title='带空格的自然数示例'
#check Nat
```

引号内可以用 `\"` 和 `\\` 表示引号与反斜线；未知转义会保留，例如 `\alpha`：

```lean check=off title="标题含 \"引号\"、\\ 与 \alpha"
-- 这是展示文本。
```

如果属性写错，插件会显示围栏错误并保持仅展示，不会猜测应该检查：

```lean check=maybe title="故意写错属性"
def unfinished : Nat :=
```

把上面的 `check=maybe` 改成 `check=off` 可以清除属性错误；改成 `check=on` 则会
检查正文，并报告不完整定义的 Lean 错误。

## Unicode 与证明目标

在块内输入 `\forall` 后按 Tab 会变成 `∀`，输入 `\to` 后按 Tab 会变成 `→`。
这是常用序列字典，尚不包含 Lean 编辑器的完整 Unicode 输入表。

把光标放在 `intro h` 和 `exact h` 之间，可以观察当前目标和局部假设：

```lean
example (P : Prop) : P → P := by
  intro h
  exact h

example : ∀ n : Nat, n = n := by
  intro n
  rfl
```

## 手动验收

1. 在编辑模式依次检查两个名为 `answer` 的块，确认都成功。
2. 修改其中一个 `answer` 的值，确认另一个块的结果不受影响。
3. 检查错误块，再检查它后面的正确证明，确认错误不会传播。
4. 在代码块上方新增说明文字，确认错误行号跟随原文移动。
5. 移动或删除一个代码块，再继续编辑其他块，确认不会出现串块诊断。
6. 快速连续输入并切换光标，确认旧目标不会覆盖新的目标。
7. 只修改一个块的 `title`，确认代码结果仍可复用。
8. 在 `check=off` 和 `check=on` 之间切换，确认只展示块不会留下旧诊断。
9. 故意写错一个属性，确认提示属性错误，且不会检查该块。

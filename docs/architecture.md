# 行为的主人

领域区分笔记中的 `ProofBlock` 和实际送入 Lean 的 `ProofDocument`。
未指定 `session` 时，一个块对应一个文档；指定后，同篇笔记中同名的参与块按原文顺序
组成一个文档。共享关系来自当前笔记，不来自点击、检查或进程运行的历史。

| 对象 | 拥有的行为 |
| --- | --- |
| `ProofBlock` | 单个围栏的身份、内容、标题、共享意图与展示策略；自身代码或检查策略变化才递增块版本 |
| `FenceMetadata` | 解析围栏的 `check` / `title` / `session`、引号和转义，拒绝无效属性并转为仅展示 |
| `SourceMap` | 单块 Lean 行列与 Markdown UTF-16 偏移的双向转换，封装缩进、换行以及关闭围栏/未关闭块末尾的边界 |
| `MarkdownBlockParser` | 识别围栏边界，交给 `FenceMetadata` 解释属性，并构造每块的位置映射 |
| `BlockCatalog` | 协调一篇笔记的块身份，跟踪增删改；唯一内容的移动可保留身份，歧义时保守创建新身份 |
| `DocumentCatalog` | 按笔记、显式 session 和文档顺序分组，排除仅展示块，跟踪文档增删、代码变化和位置变化 |
| `ProofDocument` | 组合参与块的 Lean 源码，持有文档版本和映射版本，完成跨块目标位置与诊断范围的投影 |
| `DocumentSession` | 一份逻辑文档的调度、检查状态、结果版本接受规则、诊断投影缓存与关闭生命周期 |
| `ProofWorkspace` | 笔记和文档会话协调、按文档去重的有界队列、活动块所属文档优先级、回收、目标请求取消和状态发布 |
| `LeanLanguageServerGateway` | 将文档身份映射到内存文件和 LSP 协议，防止异步启动重新打开已经关闭的文档；不解释 session |
| `ManagedLeanEnvironment` | 管理用户缓存中的基础项目，区分仅发现与显式安装，协调并发准备和状态发布 |
| `LeanToolchainDiscovery` | 发现可复用的固定版本本地工具链，避免为了探测而启动自动下载 |
| `OfficialElanInstaller` | 选择固定官方发行包、验证摘要、解包并安装私有 elan |
| `EnvironmentCommand` | 环境发现和安装命令的输出、期限与取消，独立于语言服务启动期限 |
| `LeanProjectSession` | Lake 进程、初始化、JSON-RPC 连接、启动失败与资源释放 |
| `WindowsProcessTree` | Windows 父进程已退出后的剩余子树回收，以会话时间和进程创建时间校验归属 |
| `LeanProtocol` | 不可信协议数据到应用数据的校验和转换 |
| `BoundedLog` | 保留有上限的服务输出，避免 stderr 无界积累 |
| `ObsidianProofHost` | 编辑/阅读视图对笔记的共同持有、异步读取校验、配置变更串行化、准备后的检查恢复及快照索引 |
| `LeanEnvironmentPanel` | 设置页、目标侧栏和阅读视图共用的准备、进度、取消和重试交互 |
| `LeanEditor` / `LeanEditorSession` | 按键行为、编辑器生命周期、可视区装饰、原始 Markdown 文本的高亮缓存 |
| `LeanUnicodeInput` | 常用 Unicode 序列到符号的字典规则 |
| `LeanReadingBlock` | 一个阅读视图围栏的展示、准确对应块的查找与检查按钮 |
| `LeanReadingActions` | 将实时预览中的检查按钮放到宿主源码按钮旁，等待宿主后加操作栏、在普通阅读模式回退，并释放观察器 |
| `LeanGoalView` | 目标和诊断展示，以及点击诊断时的源文档导航 |
| `LeanIconButton` | 带可访问名称、悬停说明、键盘及禁用语义的图标按钮 |
| `LeanMessagePresenter` | 分开呈现诊断级别、行列位置与可复制正文；不改写编译器消息 |
| `LeanGoalPresenter` | 依据 Lean 文本中的 `⊢` 分隔已知条件与目标，保留原始证明文本 |
| `LeanI18n` | 读取 Obsidian 语言、选择中英词典并替换 UI 文案参数；旧 API 缺失时回退英文 |
| `LeanSyntax` / `LeanPresentation` | 基础词法着色与状态文字，均不承担证明正确性的判断 |
| `LeanSettings` / `LeanSettingsTab` | 配置默认值、范围校验和设置交互 |
| `LeanProofPlugin` | 组装各层、注册 Obsidian 扩展和命令、持久化配置及卸载入口 |

`LeanGateway` 是应用层定义的端口。领域层不依赖 Obsidian、CodeMirror、Node.js、
文件路径或 LSP URI；基础设施适配该端口，插件入口负责组装。

```text
Obsidian 适配层 ──→ 应用层 ──→ 领域层
基础设施适配层 ──→ 应用层端口
```

对象之间交换文档和只读快照。界面不直接调用 JSON-RPC，也不自行保存一份检查状态机。
会话运行时状态不写进笔记；关闭、重开之后按当前内容重新建立会话。
块身份用于展示和定位，文档身份用于同步、排队与文件 worker 生命周期；两个身份不再混用。
光标改变时，工作区通过应用端口取消旧目标请求；适配层再转换为协议取消。
文档版本、映射版本、块身份和会话校验仍然保留，避免忽略取消的服务把旧结果重新带入界面。

共享文档只按顺序组合参与块的原文，在必要的块边界补换行；不会提升 `import`、插入命名空间，
或为块自动生成定理包装。第一参与块的导入与声明自然成为后续块的上下文，组内错误也可能
影响后续内容。不同笔记永远由不同 `DocumentCatalog` 管理。

块自身版本与文档版本分别回答“这一块改了吗”和“送入 Lean 的上下文改了吗”。
修改前块时，后块自身版本可以不变，但所在文档版本递增，旧诊断和目标不能继续冒充当前结果。
正文、标题与围栏位置变化不改变组合源码；`ProofDocument` 单独递增映射版本，
`DocumentSession` 按新位置重新投影已接受的诊断。跨块范围拆到实际相交的块上，
没有真实代码位置的消息保留为文档级消息，不随意挂到某个块。

基本使用不需要用户拥有项目。`ManagedLeanEnvironment` 在用户缓存中生成最小的固定版本
环境，`LeanToolchainDiscovery` 只查找本地已安装工具；只有用户执行准备操作，才进入
安装路径。已有项目仍通过高级配置注入语言服务。创建基础项目、安装工具和检查文档
各有明确的生命周期，不把安装等待塞进 LSP 的启动超时。

围栏属性属于领域规则：`FenceMetadata` 保留展示标题和共享名称，同时决定是否允许检查；
无效属性直接进入仅展示状态。UI 从领域快照取得属性，不在编辑和阅读模式各自解析一套。
`title` 的更改只是展示变化；`check` 和 `session` 的更改交由 `DocumentCatalog`
重新决定参与关系，而不是让 UI 或协议适配器维护第二份分组规则。

进程回收有明确的平台边界：正常关闭时 Windows 使用存活父进程的进程树，
Unix 使用本会话的进程组。Windows 异常退出后的补救根据当前进程快照恢复子树；
若中间祖先进程也已经退出，快照无法恢复断开的历史关系，因此不承诺任意崩溃下的
所有后代都能被追溯。该限制不改变文档会话和 RPC 连接的释放责任。

生产代码不通过顶层函数承载行为。需要回调的库 API 由对应对象注册闭包，
让回调继续访问明确的对象状态。少量静态方法承担构造或同一边界内的转换规则；
不把无关逻辑放进 `Utils` 类来满足语法形式。

`npm run check:architecture` 检查顶层函数与反向导入，但不能判断一个类的职责是否合理。
新的行为应该先回答“哪个对象掌握完成此行为所需的信息、承担失败后果”，
再决定方法的位置，而不是为每个函数机械新增一个 service。

语言属于展示边界。`LeanI18n` 翻译操作、状态和环境说明，领域对象与 Lean 协议不依赖语言设置；
源码、目标、编译器诊断和后台原始错误详情原样保留。
图标位置由 `LeanReadingActions` 适应宿主真实 DOM，`LeanReadingBlock` 仍拥有检查动作，
不复制或改造宿主的源码按钮。

# 性能记录

## 可复现基准

```sh
npm run bench
npm run bench -- --output docs/performance-results.json
```

脚本用现有 esbuild 在内存加载实际的 `MarkdownBlockParser`、`BlockCatalog` 和 `DocumentCatalog`，
模块编译、加载不计入样本。每个场景预热 8 次，测量 40 次，保留正常分配与垃圾回收开销。
保留原有的独立块基线：笔记由确定性的中文说明、Unicode 和默认 `lean` 围栏组成，
用于比较解析与块目录的成本，尚不包含文档分组。

另有 1,000 块 / 100 个命名 session 的数据集，每组 10 块，交错放置在笔记中，
每块带有 `session` 和 `title`。共享场景从完整 Markdown 更新 `BlockCatalog`，
再更新真实的 `DocumentCatalog` / `ProofDocument`。每次都校验身份、变化集和版本：
正文与标题变长只更新映射，不递增文档版本；修改第一块的定义只能改变它所属的一组。
这些断言的少量开销计入样本。

**这些数字不是从按键到检查完成的延迟。** 基准不包含 Obsidian/CodeMirror 界面、
IPC、环境发现/下载、Lean 启动、证明 elaboration 或 Mathlib 导入；它们需要分别测量。

## 已实施的资源策略

- 仅在光标进入块或手动检查时启动所属 Lean 文档；仅展示块不占用 Lean 文档。
- 无名块各有一份文档，同名 session 在本篇笔记内共用一份文档；队列和状态按文档去重。
- 代码变化按所属文档同步；正文变化更新位置映射，不增加文档内容版本。
- 标题变化只更新展示，`check=off` 或无效围栏属性不会消耗 Lean 文件 worker。
- 默认输入防抖为 200 ms，并有最长等待窗口，避免持续输入使检查无限后延。
- 默认最多保持 4 个打开的文档，默认待发队列最多 64 个；全篇检查分批填充队列。
- 默认 60 秒回收非活动的空闲文档，关闭笔记和卸载插件时释放会话。
- 光标或代码改变时主动取消旧目标请求，避免新光标等待旧的慢请求；仍按版本和
  会话状态校验结果，过期结果不覆盖最新内容。
- 编辑器只为可视区生成装饰，词法结果按原始 Markdown 内容缓存，保留 CRLF
  和缩进的准确位置；单块超过 200,000 字符时停止着色，原文仍可展示。
- Host 按笔记和块身份建立快照索引，界面查询不必反复筛选所有笔记。
- 服务启动和请求分别有默认 30 秒和 15 秒期限；取消后仍未收到响应的请求最多
  保留 32 个，超过后终止异常连接。stderr 日志只保留最后 16,384 个字符。
- 基础环境的准备与语言服务启动分离；下载工具链的等待不占用 LSP 的 30 秒启动期限。
  本地发现结果会被复用，后续块检查不重复安装或准备项目。

共享 session 减少文件 worker 数量，但扩大了依赖范围：修改前块会使该组后续证明
需要重新检查。当前同步发送完整文档内容，由 Lean 自身的快照机制决定可复用的前缀；
插件没有自行实现证明依赖图或保证后续内容的固定重查成本。其他 session 的内容版本保持不变。

语言服务器总耗时仍由项目工具链、导入、证明复杂度、机器负载和缓存状态决定。
限制打开文档数量控制文件 worker 数量，但不等于对 Lean 总内存设定硬上限。
当前解析仍是整篇扫描；超大笔记若成为实际瓶颈，应优先测量快照/装饰更新，再决定
是否增加增量围栏索引，而不是只依据这个合成基准增加复杂度。
